So, I've made a virtual environment with virtualenv, used venv-pack to create an archive of it, and I'm trying to submit this job with

Yeah, it has no problem with the main method being on S3. From the logs, it actually is downloading the archive from S3 and distributing it to the task nodes. The linked tutorial says that you need to set PYTHON_PATH, which is what the spark.pyspark.python conf option is doing. Without that, it'll throw import errors for third-party packages.
是的，主方法在 S3 上没有问题。从日志来看，它实际上是从 S3 下载归档文件，并将其分发到任务节点。相关的教程说你需要设置 PYTHON_PATH，这正是 conf 选项所做的事情。没有这个设置，它会对第三方包抛出导入错误。

It is OK to put the python to be executed on s3, it works on my side with :
将待执行的 Python 代码放在 S3 上是没问题的，在我的环境中可以正常工作：

time spark-submit --name $name \
--master k8s://${apiserver} --deploy-mode cluster --driver-cores 1 --driver-memory 1g --num-executors 2 --executor-cores 1 --executor-memory 1g\
 --conf spark.ui.enabled=false\
 --archives s3a://jlu/app/pyspark_conda_env.tar.gz\
 --conf spark.kubernetes.file.upload.path=/opt/spark/workdir\
 --conf spark.pyspark.python=/opt/spark/workdir/pyspark_conda_env.tar.gz/bin/python\
 --conf spark.kubernetes.namespace=${KUBE_NS}\
 --conf spark.kubernetes.authenticate.driver.serviceAccountName=${sa}\
 --conf spark.kubernetes.container.image=pepitedata/spark-hadoop:3.4.1-3.3.6\
 --conf spark.hadoop.fs.s3a.impl=org.apache.hadoop.fs.s3a.S3AFileSystem\
 --conf spark.hadoop.fs.s3a.path.style.access=true\
 --conf spark.hadoop.fs.s3a.endpoint="https://minio.data.svc.cluster.local:443"\
 --conf spark.hadoop.fs.s3a.access.key="xxx" --conf spark.hadoop.fs.s3a.secret.key="xxx"\
 --conf spark.hadoop.fs.s3a.connection.ssl.enabled=true\
 --conf spark.driver.extraJavaOptions="-Dfile.encoding=utf-8 -Dcom.amazonaws.sdk.disableCertChecking=true" --conf spark.executor.extraJavaOptions="-Dfile.encoding=utf-8 -Dcom.amazonaws.sdk.disableCertChecking=true" \
s3a://jlu/app/pi.py
However, to use the --archives option with an s3a path due to the fact that the s3 endpoint must be accessible from the kubernetes cluster hosting spark driver and executor pods and also from the client terminal doing the spark-submit command.
然而，由于 s3 端点必须可从托管 Spark 驱动程序和执行器容器的 Kubernetes 集群以及执行 spark-submit 命令的客户终端访问，因此需要使用带有 s3a 路径的选项。

This is not my case and I got the exception :
这不是我的情况，我遇到了异常：

com.amazonaws.SdkClientException: Unable to execute HTTP request: minio.data.svc.cluster.local: Name or service not known:

If your s3 endpoint is accessible from anywhere it should work.
如果你的 s3 端点可以从任何地方访问，那么应该可以正常工作。

The executable file (s3a://jlu/app/pi.py ) does not need to be accessible from the local client doing the spark-submit command
可执行文件（s3a://jlu/app/pi.py）不需要从执行 spark-submit 命令的本地客户终端访问。
