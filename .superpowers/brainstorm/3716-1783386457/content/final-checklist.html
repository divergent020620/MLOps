第 4 题（Hive Metastore）为什么关键

情况用户写 SQL 的方式
有 Hive Metastorespark.sql("SELECT * FROM db.table WHERE dt='20260701'")
→ 业务人员零学习成本，跟之前写 JDBC SQL 一模一样
没有 Metastore需要先建临时视图：
df = spark.read.parquet("hdfs:///path/db.db/table/")
df.createOrReplaceTempView("table")
→ 然后才能 spark.sql("SELECT * FROM table")
→ Cube Studio 可以把这个过程对用户隐藏

两种情况的最终效果

有 Metastore无 Metastore
用户写 SQL直接写，跟以前一样直接写 + 选数据集
Spark 读数据自动定位 parquet 文件Cube Studio 预定义表→路径映射
ML 训练spark.sql("SELECT features FROM table")预读成 DataFrame → 注册临时视图
Java JDBC 业务指向 Spark Thrift ServerCube Studio API 封装

一句话总结

有 Metastore：业务人员直接写 SQL，Spark 自动搞定一切。
没有 Metastore：Cube Studio 帮你隐掉路径细节，用户看起来还是写 SQL。

不管哪种，你的 HDFS keytab + 已知路径 = 底层已经通了。
