PySpark 分布式计算 —— 核心概念

500 个共享计算节点，重点解决依赖分发问题

Spark 架构

Driver（主节点）
  • 解析代码、构建 DAG 执行计划
  • 分配 Task 给 Executor
  • 收集结果
  • 依赖：需要完整 Python 环境
Executor × 500（工作节点）
  • 执行 Task（map/filter/apply）
  • 每个 Executor 是独立 JVM 进程
  • 通过 Py4J 调用 Python
  • 依赖：需要 Python + 与 Driver 一致的库
Cluster Manager
  • YARN / K8s / Standalone
  • 管理节点资源分配
  • 这 500 个节点由别人的集群管理

你面临的核心问题

问题说明
❌ 不能装依赖500个节点是别人的，不能 pip install torch/numpy/scipy
⚠️ 最多有 Python节点上只有基础 Python，没有 ML 库
📦 依赖要分发每次提交任务时把依赖打包分发到 500 个 Executor

解法：依赖打包 + 运行时分发

方案原理包大小适用
--archives (conda env zip)整个 conda 环境打成 tar.gz，解压到每个 Executor200MB~1GB完整 ML 环境
--py-files (zip/egg)纯 Python 包打成 zip，加入 PYTHONPATH10~50MB纯 Python 依赖
Spark MLlib 原生Spark 内置算法，无需额外依赖0LR/RF/GBDT/KMeans
PySpark UDF + 模型文件模型文件广播 + 纯 Python 推理代码几MB仅推理

推荐组合策略

训练场景：--archives 分发 conda 环境（含 torch/sklearn）
→ 虽然 200MB+，但分发给 500 节点一次，后续 Task 复用解压好的环境

推理场景：模型广播 + 纯 NumPy 推理代码
→ 模型 .pkl / .onnx 文件 <10MB，广播到所有 Executor，无需大型依赖
