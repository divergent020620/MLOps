PyTorch 训练 + ONNX 推理 on YARN

Docker 环境无 conda，目标：把 PyTorch/ONNX Runtime 分发到 500 个 YARN 节点

推荐组合策略

训练阶段venv 打包 PyTorch(~800MB) → YARN --archives 分发给 50-100 个 GPU Executor → 数据并行训练 → model.pt
转换阶段torch.onnx.export(model.pt) → model.onnx(10-200MB)
推理阶段轻量 venv(onnxruntime+NumPy, ~50MB) → YARN --archives 分发给 500 个 CPU Executor → 广播 model.onnx → mapInPandas 批量推理

A. 训练：Spark + TorchDistributor (Spark 3.4+)

原理：每个 Executor 启动一个 PyTorch 进程，gloo/NCCL 后端通信做 all-reduce 梯度同步

# 打包环境
python -m venv /tmp/train_env
source /tmp/train_env/bin/activate
pip install torch numpy pandas
tar -czf train_env.tar.gz -C /tmp train_env
hdfs dfs -put train_env.tar.gz /user/ml/envs/

# 提交训练
spark-submit --master yarn --deploy-mode client \
  --num-executors 64 --executor-cores 4 --executor-memory 16G \
  --archives hdfs:///user/ml/envs/train_env.tar.gz#venv \
  --conf spark.executorEnv.PYSPARK_PYTHON=./venv/bin/python \
  train.py

B. 推理：ONNX + mapInPandas（最轻量）

ONNX Runtime 依赖仅 30MB，模型文件 10-200MB → 广播到 500 个 Executor

pip install onnxruntime numpy pandas -t ./infer_deps
cd infer_deps && zip -r ../infer_deps.zip ./
hdfs dfs -put infer_deps.zip /user/ml/envs/

def infer_batch(iterator):
    import onnxruntime as ort
    sess = ort.InferenceSession(bc_model_bytes, providers=['CPUExecutionProvider'])
    for pdf in iterator:
        inputs = pdf.to_numpy().astype(np.float32)
        out = sess.run(None, {'input': inputs})
        yield pd.DataFrame(out[0])

关键问题确认

Spark 版本？3.4+ 有 TorchDistributor，老版本需要手动 torchrun
节点 Python 版本？必须跟你打包的 venv Python 大版本一致(3.9/3.10)，否则 venv 无法启动
500 节点有 GPU 吗？有 GPU → 训练用 GPU Executor；全 CPU → 训练只能 CPU 慢跑，推理 OK
HDFS 权限？数据在哪？venv 包需要上传 HDFS 让 YARN 能访问
