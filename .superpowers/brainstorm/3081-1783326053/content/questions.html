你需要向集群管理员确认的全部信息

拿着这份清单去问，一次搞清楚，不用来回跑

一、Spark / YARN 环境

#问题为什么需要知道
1Spark 版本是多少？（spark-submit --version）3.4+ 有 TorchDistributor 直接训练；老版本需手动 torchrun
2有没有 spark-submit 权限？在哪台机器上提交？需要 Gateway/Edge 节点地址
3YARN ResourceManager 地址？spark-submit 需要 --master yarn://RM:8032
4YARN 队列名(queue)是什么？资源配额多少？提交任务要指定队列，配额决定能用多少 Executor
5每个 NodeManager 最多给多少 Container？内存/CPU 限制？决定 --executor-memory 和 --num-executors 该设多少

二、节点环境

#问题为什么需要知道
6500 个节点有 GPU 吗？什么型号？多少张？决定训练能不能用 GPU、ONNX 推理用 CPU 还是 GPU
7节点操作系统和架构？(cat /etc/os-release; uname -m)决定 Python 包用什么平台编译（linux x86_64 / aarch64）
8节点上 Python 版本？(python3 --version)venv 的 Python 版本必须跟节点一致，不然启动报错
9节点上有没有基础 Python 包？(pip list)如果有 NumPy/Pandas 就不需要重复打包，省体积
10有没有 glibc 版本限制？(ldd --version)PyTorch 的 .so 需要 glibc >= 2.17，太老的 CentOS 6 可能不行

三、HDFS 和认证

#问题为什么需要知道
11HDFS 地址？（NameNode 和端口）读写数据、上传 venv 包都需要
12keytab 认证怎么用？kinit 命令是什么？HDFS 和 YARN 都走 Kerberos，需要先 kinit 才能操作
13我的 HDFS 目录在哪？读写权限？容量限制？数据放哪、venv 包放哪、输出写哪
14YARN 是否也需要 keytab 认证？spark-submit 可能需要 --principal --keytab 参数

四、网络和权限

#问题为什么需要知道
15NodeManager 之间网络通吗？端口有限制吗？PyTorch 分布式训练需要 Executor 间 TCP 通信(all-reduce)
16能访问外网吗？还是纯离线？离线环境 pip install 需要提前下载 wheel
17--archives 文件大小有限制吗？venv 包 500MB-1GB，有些集群限制 archives 大小
18有没有 YARN 本地目录空间限制？venv 解压到 yarn.nodemanager.local-dirs，空间要够

五、你现在就有的东西

keytab 文件用于 kinit 认证，访问 HDFS 和 YARN
Docker 镜像Notebook 和推理环境，里面已经装了 PyTorch/ONNX Runtime
krb5.confKerberos 配置文件（你有吗？）

对方大概率会反问你

你需要多少资源？训练：50 Executor × 4核 × 16G 内存 + 1 GPU = 共 200 核 / 800G 内存 / 50 GPU
推理：200 Executor × 2核 × 8G 内存 = 共 400 核 / 1.6T 内存
你要跑多久？训练单次 2-8 小时；推理按数据量线性扩展
你需要装什么？不需要在节点上装任何东西！全部通过 venv 包 + YARN --archives 运行时自动分发
