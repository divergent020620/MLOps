基于你现有项目的 Spark 训练/推理方案

你已经有：HDFS Kerberos客户端、Dataset管理、Notebook内置Spark 3.1.3

当前资产盘点

DONEHDFS Kerberos客户端 (keytab + kinit)
DONEHDFS 浏览器 + 数据集下载/拉取
DONENotebook 内置 PySpark (3.1.3) + Hadoop + JDK8
DONEPySpark YARN 示例代码 (spark-submit from notebook)
GAP远程集群的 Spark 版本 ≠ 你 Notebook 的 3.1.3 (需要匹配)
GAPyarn-site.xml 要指向远程集群的 ResourceManager
GAP无 PyTorch/ONNX Runtime 分发方案

两步走方案

1问管理员拿到远程集群 Spark 版本 → 看情况决定客户端
- 版本跟你 Notebook 的 3.1.3 兼容 → 直接改 yarn-site.xml 指向远程 RM
- 版本不同 → 在 Gateway 机器上直接用集群自带的 spark-submit
- 最低要求：只要能 spark-submit，PySpark 代码不需要改
2打包 Python venv → 上传 HDFS → spark-submit --archives 分发
训练: venv 含 PyTorch(~800MB) → YARN 分发给 GPU Executor
推理: 轻量 venv 含 ONNX Runtime(~30MB) → YARN 分发给 CPU Executor
你的现有 HDFS 客户端已经能上传，keytab 已经能认证

Spark 版本兼容策略

远程集群版本你的 Notebook 兼容性分布式训练选择
3.1.x直接兼容，改 yarn-site.xml 即可torchrun 手动分布式
3.2.x / 3.3.x小版本不兼容，需在 Notebook 换 Sparktorchrun 手动分布式
3.4.x / 3.5.x不兼容，需升级。但升级后好处大可直接用 TorchDistributor API

最简单的问法

问管理员 5 个问题：

1. Spark 版本是多少？
2. YARN ResourceManager 地址和端口？
   (对应 spark-submit --master yarn://xx.xx.xx.xx:8032)
3. 有没有 Gateway 机器让我 ssh 上去执行 spark-submit？
   如果没有，我从我的 Notebook 提交，需要开网络白名单吗？
4. 节点 Python 版本？(python3 --version)
5. 500 个节点有 GPU 吗？型号？

拿到信息后的实施路径

阶段操作
1. 验证连通spark-submit --master yarn://RM:8032 跑一个 Pi 示例确认通
2. 打包 venv从 Docker 镜像 pip install torch/onnxruntime → tar.gz → hdfs dfs -put
3. 提交训练spark-submit --archives hdfs:///venv.tar.gz#venv --conf spark.executorEnv.PYSPARK_PYTHON=./venv/bin/python
4. 提交推理广播 model.onnx + mapInPandas → 500 节点并行推理
