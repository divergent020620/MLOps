PySpark 分布式计算核心概念

主题：500 个共享计算节点下的依赖分发策略

Spark 架构——3 个角色

Driver（驱动器）

解析 Python 代码
构建 DAG 执行计划
切分 Task 分配给 Executor
最后收集结果汇总

→ 需要完整 Python 环境

Executor × N（执行器）

每个节点上一个 JVM 进程
通过 Py4J 调用 Python
真正执行 map/filter/apply
各 Executor 之间不通信

→ 需要跟 Driver 一致的库

Cluster Manager

YARN / K8s / Standalone
管理 500 个节点的资源
分配 Executor 给不同应用
监控心跳、处理故障

→ 别人的集群，你没管理权限

朴素例子：一个词频统计的完整执行过程

# --- 你写的 Python 代码 ---
df = spark.read.text("hdfs:///data/books/*.txt") # L1 只定义
words = df.select(explode(split(df.value, " "))) # L2 只定义
counts = words.groupBy("value").count() # L3 只定义
counts.write.csv("hdfs:///output/") # L4 触发执行 ↓

Spark 内部执行过程：

Step 1L1-L3 构建逻辑计划（DAG）：TextScan → Split → GroupBy → Write
Step 2L4 触发 Action，DAG Scheduler 把计划切成物理 Stage
Step 3每个 Stage 切分成 N 个 Task（= Partition 数），Task 发给 500 个 Executor 并行跑
Step 4Executor-1 读 book1.txt 切片 → 分词 → 局部统计 → shuffle → 最终结果
Step 5所有 Executor 结果汇总 → 写入 HDFS

核心概念：RDD vs DataFrame、Transformation vs Action、Partition

概念一句话说明
RDD底层抽象，分布式对象集合，无 schema
DataFrameRDD + Schema + SQL 优化器 = 有列名的分布式表
Transformation惰性操作：map/filter/groupBy/join → 只构建计划，不执行
Action触发操作：show/collect/count/write → 真正触发分布式计算
Partition数据分片，一个 Partition = 一个 Task。Partition 越多并行度越高
Shuffle数据跨节点重新分区（groupBy/join 触发），最昂贵的操作
