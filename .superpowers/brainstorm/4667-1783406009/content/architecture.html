3 种方案对比

A

新建 spark-client 镜像（推荐）

基于 jupyter-ubuntu22.04，只装 Spark 2.4 + Hadoop 配置 + Kerberos。干净、体积小、和现有镜像不冲突

优点

  • 独立可控，不影响现有 bigdata 镜像
  • 只装必要的，镜像体积小
  • CDP 配置和 K8s 内部配置隔离

缺点

  • 需要新建一个镜像 variant
  • PyTorch/ML 库要额外装或靠 venv
B

改造 bigdata 镜像

把 bigdata 镜像中的 Spark 3.1.3 换成 2.4，配置换成 CDP 的 XML

优点

  • 复用已有的 JDK/Maven/大数据工具
  • 基础 ML 库已安装

缺点

  • 破坏现有 bigdata 镜像（K8s YARN）
  • Spark 3→2 降级可能影响已有 Flink/PySpark 示例
C

Spark 也放进 venv

镜像里什么都不装，PySpark + PyTorch + ONNX 全部打进 venv tar.gz，运行时上传

优点

  • 镜像最简单，无 Spark 版本绑定

缺点

  • venv 体积巨大（PySpark ~300MB + PyTorch ~200MB）
  • 每次 spark-submit 都要上传 PySpark JAR
  • spark-submit 命令本身还需要 Spark 客户端

推荐方案 A

新建一个 images/jupyter-notebook/spark-client/ 目录，Dockerfile 基于 jupyter-ubuntu22.04，只追加 Spark 2.4 + CDP 配置 + Kerberos 客户端。PyTorch/ONNX/sklearn 等深度学习库全部打进 venv，不在镜像里装。
