Pipeline 执行流程

1
用户创建 Pipeline 前端 DAG 编辑器 → 定义 Task 节点 → 每个 Task 引用一个 Job_Template
↓
2
提交运行 POST /pipeline/run → home.py run_pipeline() → 解析 DAG JSON
↓
3
生成 Argo Workflow CRD DAG → Argo Workflow YAML (DAG/Steps 模板) → 提交到 K8s pipeline 命名空间
↓
4
py_k8s.py 注入 Pod 配置 make_pod() → DNS + HostAliases + GLOBAL_ENV 模板渲染 + 资源限制 + Volume 挂载
↓
5
K8s 调度执行 Argo Controller → 创建 Pod → 容器运行 → GLOBAL_ENV 变量 ({{pipeline_id}}, {{creator}}, {{uuid}} 等)
↓
6
Watch 状态同步 Watch 部署 → 轮询 Workflow 状态 → 回写 MySQL (Pipeline/Task 状态)

Notebook 生命周期

1
用户创建 Notebook 选择镜像 + 资源配置 (CPU/GPU/Memory) + 挂载数据集
↓
2
view_notebook.py 处理 创建 Notebook DB 记录 → 调用 py_k8s.py create_deployment()
↓
3
K8s 创建 Pod jupyter 命名空间 → Jupyter/VSCode 容器 → NodePort/Ingress 暴露
↓
4
用户访问 浏览器 → Nginx 反代 → K8s Service → Notebook Pod
↓
5
自动回收 Celery Beat schedules.py → 检查空闲超时 → 自动停止/删除

模型推理服务

1
训练完成 → 模型注册 Training_Model 表记录模型元数据 + 模型文件路径 (HDFS/本地)
↓
2
创建 InferenceService 选择模型 + 资源配置 + 扩缩容策略 → view_inferenceserving.py
↓
3
K8s 部署推理 Pod service 命名空间 → Deployment / StatefulSet → 模型加载
↓
4
Istio VirtualService 路由 py_network.py → 创建 VirtualService CRD → 流量路由 + 金丝雀发布
↓
5
外部调用 Istio Gateway → VirtualService → 推理 Pod → 返回预测结果

容器启动流程 (entrypoint.sh)

1
创建符号链接 workspace / dataset / aihub 目录映射
↓
2
初始化数据库 python create_db.py → 创建所有表
↓
3
Redis 分布式锁 SET cube:db-upgrade-lock NX EX 120 → 获取锁 → 最多重试 30 次
↓
4
数据库迁移 myapp db upgrade (Alembic) → 释放 Redis 锁
↓
5
创建管理员 & 初始化 fab create-admin → myapp init → 种子数据 (模板/流水线/数据集)
↓
6
STAGE 分支 build → npm build 前端 | dev → Flask runserver | prod → Gunicorn

完整请求链路

Browser → Nginx :80 → Flask before_request → Auth (Cookie/Header) → View Handler → K8s API → Pod Running
认证方式 (before_request)
  • myapp_username Cookie (跨域)
  • Authorization Header
  • 白名单: /static, /login, /health
  • 支持 DB / LDAP / REMOTE_USER
GLOBAL_ENV 模板变量
  • {{pipeline_id}} — 流水线 ID
  • {{creator}} — 创建者
  • {{uuid.uuid4().hex}} — 唯一 ID
  • {{step_name}} — 步骤名称
