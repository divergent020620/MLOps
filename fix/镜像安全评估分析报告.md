> **2026-09-04 更新**:行内已明确**必须使用 py3.12**(py3.9 不再允许)。现行 py3.9 麒麟链(kylin-20260730-v6)的整改已决定**跳过**——本报告的 rpm 层修复目标不再执行;pip 层修复目标(FAB/Jinja2/Werkzeug 等)与 npm 层处理(不装 node16)并入 py3.12 新镜像构建,详见整改方案。

## 1. 结论速览

1. 麒麟版镜像(`192.168.11.12/cube-studio/kubeflow-dashboard:kylin-20260730-v6`)评估结果:超危 **8 个 CVE**(11 条组件-漏洞)、高危 **45 个 CVE**(64 条);超危组件 10 个、高危组件 31 个。评估平台管控策略:高危及以上组件一律"**禁止**"。
2. **重要发现:该镜像的 Python 是 Miniconda 结构**(`/root/miniconda3` base 环境 + `envs/python39` 应用环境),与仓库 `install/docker/Dockerfile-base.kylin`(yum 装 python39)的描述不一致 → kylin-20260730-v6 是用另一套(未入库或旧版)脚本构建的,**整改前必须先找回真实构建脚本**(见 §6)。
3. 超危大头:perl 5.28.3(**9.8**)、conda base 的 certifi 2023.5.7(**9.8**)、libxml2 2.9.10(**9.1×2**)、flask-appbuilder(**9.1**)、npm ip(**9.8**)、glibc 2.28(**7.8**)、PyMySQL(**6.3**)。
4. rpm 层的全部问题都是**麒麟系统包补丁没跟上**(评估平台已给出 p11/p12 补丁版),行外联网 `yum update` 一次即可销项。
5. 本次"中危/低危 = 0"很可能是评估平台只导出了超危/高危,请确认输出设置(见 §6),避免误以为镜像整体干净。
