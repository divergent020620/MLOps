# 行内 K8s 切换检查单(M1 py3.12 镜像换量)

> 一句话:按"方式 B(Dockerfile 法)"构建 + 下面 6 步执行,即可换镜像;**唯一必须先做的硬动作是更新 ConfigMap(config.py 适配版)**——否则新镜像启动即崩。

## 一、换镜像前必须执行的 4 个动作(缺一不可)

### ① 更新 ConfigMap(config.py 必须换!!)
行内 `kubeflow-dashboard-config` 的 config.py 现在是旧版(含 `import imp`、`CACHE_TYPE='redis'`)——**py3.12 下启动即崩**。用适配版替换:
```bash
# 适配版在交付包: install/kubernetes/cube/overlays/config/{config.py, entrypoint.sh, project.py}
kubectl create configmap kubeflow-dashboard-config \
  --from-file=config.py=install/kubernetes/cube/overlays/config/config.py \
  --from-file=entrypoint.sh=install/kubernetes/cube/overlays/config/entrypoint.sh \
  --from-file=project.py=install/kubernetes/cube/overlays/config/project.py \
  -o yaml --dry-run | kubectl apply -f -
```
(或按行内惯例经 kustomize 更新同名 ConfigMap;三件套都要换,entrypoint.sh/project.py 若与现网一致可按现网为准)

### ② 镜像 tag 切换(4 个 deployment 共用后端镜像)
```bash
kubectl set image deployment/kubeflow-dashboard        kubeflow-dashboard=10.240.125.39/cube-studio/kubeflow-dashboard:app-p312-v1
kubectl set image deployment/kubeflow-dashboard-schedule kubeflow-dashboard=10.240.125.39/cube-studio/kubeflow-dashboard:app-p312-v1
kubectl set image deployment/kubeflow-dashboard-worker  kubeflow-dashboard=10.240.125.39/cube-studio/kubeflow-dashboard:app-p312-v1
kubectl set image deployment/kubeflow-watch            kubeflow-dashboard=10.240.125.39/cube-studio/kubeflow-dashboard:app-p312-v1
kubectl rollout status deployment/kubeflow-dashboard -n infra
```
> 注意 deploy yaml 中 `imagePullPolicy: Always`,新 tag 拉取无需额外操作;前端镜像不动。

### ③ PATH 持久化(仅"方式 A 容器法"需要!)
容器法(commit)出来的镜像**继承 M0 基座 PATH,不含 `/opt/appenv/bin`** —— K8s 里 gunicorn/celery/探针会用了基座 python(无依赖)→ 全挂。方式 B(Dockerfile 法)已写 ENV,无需此步。
容器法补救:commit 前在容器内执行后重 commit:
```bash
echo 'export PATH=/opt/appenv/bin:$PATH' >> /etc/profile.d/cube312.sh
```

### ④ alembic 版本核对(行内库 vs 仓库迁移头)
```bash
docker run --rm 10.240.125.39/cube-studio/kubeflow-dashboard:app-p312-v1 bash -c \
  'cd /home/myapp && FLASK_APP=myapp:app /opt/appenv/bin/python myapp/bin/myapp db heads'
# 期望输出 a2b3c4d5e6f7(仓库 head)
# 行内库的 alembic_version 应等于或可迁移到该 head;行内曾 rm 过 a1b2c3d4e5f6 迁移文件,
# 若生产库版本表与仓库不一致, 先导出对比(见下面 ⑤ 观察), 异常截图交回
```

## 二、允许首次启动的观察指标(10 分钟)

| 检查 | 期望 | 失败动作 |
|---|---|---|
| `kubectl get pods -n infra` | 4 个 1/1 Ready | 日志截图交回 |
| 后端日志 | 无 Traceback;`gunicorn` started;`db upgrade` 前无 `import imp` 报错 | 交回 |
| `curl -s https://<域名>/health` | `OK` | 交回 |
| 登录页正常 | 200/能登入 | 交回 |
| schedule 探针 `check_celery.py` | Ready | 交回 |
| worker `celery inspect ping` | `pong` | 交回 |
| 日志出现 `Duplicate column` | **正常**(try/except 设计内),忽略 | — |
| HDFS 用例(数据集预览) | 正常 | 若 SPNEGO 报错,确认 ③-0 gssapi 已装 |

## 三、回退方案(安全网)
```bash
kubectl set image deployment/kubeflow-dashboard kubeflow-dashboard=10.240.125.39/cube-studio/kubeflow-dashboard:kylin-20260730-v6
# ... 其余 3 个同; ConfigMap 同步回旧版(或用 git 恢复到 15.0 之前的 config.py)
```
旧镜像与旧 ConfigMap 在,回退 5 分钟内完成。

## 四、结论
- **行外已验证**依赖链/启动链/CRUD/HDFS 全链(证据: py312/验证记录与行内组装指引.md §1)
- **行内唯一'换了就跑'的前提 = ① 更新 ConfigMap + ② tag 切换**;③④ 是方式 A 的补丁与首跑观察
