### M1 后端镜像(1 天,等 requirements-final.txt)

> **两种方式任选,推荐 D(可复现、构建期即断言):**
> - 方式 A(容器法,零学习成本):下面"步骤 A" 的命令照抄 + commit

```bash

# ① 材料入容器(全部已交付)

# ② myapp 源码(仓库路径按实际,与旧链 Dockerfile.kylin 一致)
docker cp myapp app-p312-01:/home/myapp/myapp
# ②' HDFS 认证原料(真实配置,与旧链一致: Dockerfile 的 COPY 行)
docker cp ai_general.keytab app-p312-01:/home/myapp/ai_general.keytab
docker cp krb5.conf app-p312-01:/etc/krb5.conf

# ③ venv + 安装(注意顺序!python3.12 = /opt/python3.12.10-x86_64-bin,勿用 python3.7!)
PIP_IDX="http://user-bdas.bdm:bdasbdmPwdNexus@10.208.29.10:8087/repository/BDAS.BDM-PY-PUBLIC/simple"
docker exec -i app-p312-01 bash -c '
python3.12 -m venv /opt/appenv
# ③-0 SPNEGO 原生后端(gssapi, 行内 HDFS 严格 SPNEGO 必装; 已编译 manylinux2014 wheel)
/opt/appenv/bin/pip install --no-index --find-links /tmp/ow gssapi decorator
# ③-1 Kerberos 组必须 --no-deps 先行(requests-kerberos 的 metadata extra 会拉 gssapi, 正常解析必挂)
/opt/appenv/bin/pip install --no-deps --trusted-host 10.208.29.10 --index-url "'$PIP_IDX'" -r /tmp/requirements-kerberos.txt
# ③-2 主依赖(全 wheel 化)
/opt/appenv/bin/pip install --only-binary=:all: --trusted-host 10.208.29.10 --index-url "'$PIP_IDX'" -r /tmp/requirements-final.txt 2>&1 | tail -8
# ③-3 4 个 sdist-only 纯 py 包走离线 wheel
/opt/appenv/bin/pip install --no-index --find-links /tmp/ow wtforms_json-0.3.5 jieba-0.42.1 hdfs-2.7.3 docopt-0.6.2 2>&1 | tail -3
/opt/appenv/bin/python -c "import myapp; print(\"myapp import OK\")" || echo "!! 请截图报错交回"
# 启动冒烟(可选): /opt/appenv/bin/python myapp/run.py & sleep 8; curl -s localhost/health
'

# ④ commit + save + 清理
docker stop app-p312-01
docker commit app-p312-01 <registry>/kubeflow-dashboard:app-p312-v1
docker save -o app-p312-v1.tar <registry>/kubeflow-dashboard:app-p312-v1
docker rm app-p312-01
```
- 部署约定:同一镜像用于 kubeflow-dashboard / -schedule / -worker / kubeflow-watch 四个 deployment(与旧链 build_backend.sh 一致)
- 改镜像时 ENTRYPOINT/CMD 保持基座配置不动
- HDFS 认证原料(**真实配置,随镜像直接 COPY,与旧链一致**):`ai_general.keytab` → `/home/myapp/ai_general.keytab`、`krb5.conf` → `/etc/krb5.conf`(旧链 install/docker/Dockerfile 即此做法;hdfs_client.py 会调 kinit)。kinit 二进制与 kadm5srv 库已在 M0 里就位

## 第六部分:已知坑(务必熟读)

1. **yum downloadonly 缓存"下个成功事务即清"** → 下载后立刻 `find /var/cache/dnf -name "*.rpm" -exec cp {} 目标/ \;`
2. **nginx 全模块 = perl 5.28.3(超危 9.8)** → 最小化 exclude 名单一个不少(文档已含)
3. **行内源落后基座**:glibc p12 / openssl-libs p34 / krb5-libs 23 都比源新 → 所有 yum 命令必须带 EXCL;装 nginx 可接受 openssl p34→p29(已测平台认可)
4. **python3 = py3.12**(PATH 优先);系统 python3.7 是 dnf 依赖,**勿动勿用**
5. **HDFS Kerberos 实测定论**:① requests-kerberos 必须 `--no-deps` 装(extra 拉 gssapi 必挂);② krbcontext 是死依赖(不装);③ **gssapi 原生后端 wheel 已编译交付**(manylinux2014,kinit→SPNEGO 全链已实测 SecurityContext OK;详见 backend/README.md §4)——先 kinit 后 SPNEGO 是配套两步,不影响行内现有模式
5. kinit 运行时需要 `/etc/krb5.conf`(行内真实配置,部署时由行内 COPY,组装期不放占位)
