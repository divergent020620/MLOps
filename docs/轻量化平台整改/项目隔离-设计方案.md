# 文件管理策略：从用户隔离改为项目隔离 — 设计方案

## 1. 当前隔离策略分析

### 1.1 现状：**按用户（username）隔离，非按项目隔离**

当前文件存储的物理目录结构：
```
/data/k8s/kubeflow/pipeline/workspace/   ← WORKSPACE_HOST_PATH（所有项目共用）
    ├── user1/                            ← subPath = username
    │   ├── pipeline/
    │   └── ...
    ├── user2/
    │   └── ...
    └── datasets/                          ← DATASET_SAVEPATH（全局共享）

/data/k8s/kubeflow/dataset/               ← 数据集（全局共享，保持不变）
/data/k8s/kubeflow/global/                ← 全局共享文件
/cube-studio/aihub/                        ← AI Hub 模型（全局共享）
```

### 1.2 隔离机制详解

**Pod 挂载方式**（`myapp/utils/py/py_k8s.py:883-917`）：

```python
# get_volume_mounts() 中 (pvc) 类型处理：
# volume_mount = "kubeflow-user-workspace(pvc):/mnt"
# → mountPath: /mnt/{username}
# → subPath: {username}
```

具体代码（`py_k8s.py:903-918`）：
```python
if "(pvc)" in volume:
    pvc_name = volume.replace('(pvc)', '').replace(' ', '')
    volumn_name = pvc_name.replace('_', '-').lower()[-60:].strip('-')
    k8s_volumes.append({
        "name": volumn_name,
        "persistentVolumeClaim": {"claimName": pvc_name}
    })
    k8s_volume_mounts.append({
        "name": volumn_name,
        "mountPath": os.path.join(mount, username),
        "subPath": username
    })
```

**关键发现**：
- 所有项目共用一个 PVC：`kubeflow-user-workspace`
- 底层 hostPath：`/data/k8s/kubeflow/pipeline/workspace`（`py_k8s.py:2342`）
- `create_workspace_pv_pvc()` 为每个 namespace 创建 PV，但 hostPath **全部指向同一个路径**
- 隔离方式：PVC 的 `subPath: {username}`，每个用户只能看到自己的子目录
- **不同项目间的同一用户，挂载的是同一个 `/mnt/{username}` 目录，文件完全互通**

### 1.3 当前问题

| 场景 | 问题 |
|------|------|
| 用户 A 在项目 1 中创建的文件 | 用户 A 在项目 2 的 notebook 中也能看到（同一 `/mnt/userA/`） |
| 项目 1 的多个用户协作 | 各自只能看到自己的文件，无法在项目内共享文件 |
| 项目间数据隔离 | 无法实现，所有数据按用户维度混在一起 |
| 项目归档/清理 | 无法按项目维度清理，只能按用户清理 |

## 2. 目标方案：按项目隔离（项目内用户共享）

### 2.1 核心模型

**一个项目 = 一个共享工作空间**。项目内所有用户看到的是同一个目录，可以共同建设。

```
项目 1（id=1）        项目 2（id=2）
┌─────────────┐      ┌─────────────┐
│ /mnt/  ←────│──    │ /mnt/  ←────│──
│ workspace/1/ │      │ workspace/2/ │
│   ├── data/  │      │   ├── data/  │
│   ├── models/│      │   ├── models/│
│   └── ...    │      │   └── ...    │
└─────────────┘      └─────────────┘
  ↑ 用户A 用户B          ↑ 用户A 用户C
  (都能看到同一内容)      (都能看到同一内容)
```

### 2.2 目标目录结构

```
/data/k8s/kubeflow/pipeline/workspace/
    ├── 1/                                 ← project_id=1，项目内所有用户共享
    │   ├── data/
    │   ├── models/
    │   └── ...
    ├── 2/                                 ← project_id=2
    │   ├── data/
    │   └── ...
    └── 3/                                 ← project_id=3
        └── ...

/data/k8s/kubeflow/dataset/               ← 数据集（全局共享，保持不变）
```

### 2.3 Pod 挂载方式变更

**变更前**：
```
subPath: {username}
mountPath: /mnt/{username}
→ 容器内路径: /mnt/user1/   （只看到自己的文件）
```

**变更后**：
```
subPath: {project_id}
mountPath: /mnt
→ 容器内路径: /mnt/   （看到项目内所有用户的文件，共同建设）
```

在 `get_volume_mounts()` 中，`(pvc)` 类型的 subPath 从 `username` 改为 `project_id`，mountPath 不再拼接 username：

```python
# 变更前
k8s_volume_mounts.append({
    "name": volumn_name,
    "mountPath": os.path.join(mount, username),   # /mnt/user1
    "subPath": username                            # user1
})

# 变更后
k8s_volume_mounts.append({
    "name": volumn_name,
    "mountPath": mount,                            # /mnt
    "subPath": str(project_id)                     # 1
})
```

### 3.2 核心改动详情

#### 改动 1：`py_k8s.py` — `get_volume_mounts()` 

```python
# 当前（py_k8s.py:883-917）
@staticmethod
def get_volume_mounts(volume_mount, username):
    ...
    if "(pvc)" in volume:
        ...
        k8s_volume_mounts.append({
            "name": volumn_name,
            "mountPath": os.path.join(mount, username),
            "subPath": username
        })

# 改为
@staticmethod
def get_volume_mounts(volume_mount, username, project_id=None):
    ...
    if "(pvc)" in volume:
        ...
        if project_id:
            sub_path = str(project_id)
            mount_path = mount  # /mnt（不拼接 username）
        else:
            sub_path = username
            mount_path = os.path.join(mount, username)
        k8s_volume_mounts.append({
            "name": volumn_name,
            "mountPath": mount_path,
            "subPath": sub_path
        })
```

## 6. 风险与注意事项

| 风险 | 缓解措施 |
|------|----------|
| 项目内用户误删彼此文件 | 可用 `(pvc-share)` 挂载只读共享目录；或通过容器内权限控制 |
| notebook 路径变化 | 用户脚本中硬编码的 `/mnt/{username}/` 需要更新为 `/mnt/` |
| 项目间完全隔离 | 通过 subPath 在 K8s 层面强制隔离，容器内无法跨项目访问 |
| 尚未部署，无存量数据 | 无需迁移，直接按新方案部署 |
