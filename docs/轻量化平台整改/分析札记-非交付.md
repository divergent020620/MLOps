> **`产品交付物/` 与 `决策分析.md` 里不出现这些内容**——交付物只写结论和依据，不写"我改过什么"。

## 一、四次"拿局部环境推断项目状态"的错

分析过程中反复踩同一个坑：**把当前开发环境（5 节点实验室）的现状，当成了整个项目的状态。**

| # | 看到的 | 错误推断 | 实际 |
|---|---|---|---|
| 1 | DB `run` 表 0 条 | 流水线没人用，可下线 | 开发环境还没跑真实业务 |
| 2 | 全集群无 GPU / 无 HDFS | 训练不做 / HDFS 浏览是死代码 | 训练走行内 **YARN**；HDFS 浏览是二开成果并已联调 |
| 3 | 离线包无 `dataset:20250301` | 取数存数要自建 | 已开发完、行内验证过（自研路径，不用那个模板） |
| 4 | 离线包无中间件 UI 镜像 | 镜像不存在 → F5 排下一期 | **只是我这边看不到**（行内开发、行内上线） |
| 附 | 离线镜像包 48 个 tar、节点 `crictl images` | 当成项目缺口清单 | 只是**开发环境的介质盘点** |

**规则**：
- 开发环境只用于判断"**我这边能不能跑**"，**不用于判断项目缺口**。
- **行内信息只认用户口述**，不认代码/清单/集群里看到的东西。
- 受此影响需重判的：`docs/项目模块/集群组件盘点与精简方案.md` 的"建议砍 XX"结论、F5 的交付批次、任务模板的工作量。

## 二、"已完成"其实是三态，不是两态

用户原话：**"推理服务啥的我也都测试过了啊。只是说从现在的使用上来说肯定不好用。"**

| 状态 | 含义 | 谁的问题 |
|---|---|---|
| ① 没做 | 功能不存在 | 研发 |
| ② 做了但跑不通 | 环境/依赖不满足 | 工程 |
| ③ **能跑但不好用** | 技术验证通过，体验差 | **产品** |

**"测试过了"只证明 ② 解决，不证明 ③ 解决。**
一度把 ③ 全归进"已完成"，导致把可用性改造排除在一期范围外——**而它恰恰是一期主力**。

---

## 三、被逐个纠正的"其实已经做完了"

这三项我都误判为"待验证 / 要从零建"，实际都已由用户完成并在行内验证：

- **分布式训练** —— 走既有 YARN 集群（`hadoop` 模板）
- **取数存数** —— 自研实现
- **HDFS 数仓浏览** —— 已联调

**教训**：不要把 seed 里引用的东西当成实现所依赖的东西（`init-job-template.json` 的 `dataset` 模板 ≠ 取数存数的依赖）。
**与其一个个猜，不如一次性问清"还有哪些做完了"。**
