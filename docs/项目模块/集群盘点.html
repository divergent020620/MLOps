02存储链路：整个平台的根是一块 NFS 盘

从上往下追，Pod 拿到的是一个"持久卷"，一路追到底是一台机器的本地磁盘外加一个 NFS 导出。

1
Pod 挂载 PVC
15 个 PVC：kubeflow-user-workspace、kubeflow-dataset、infra-kubeflow、minio-pvc、kubeflow-global-pvc …
2
PV 是 hostPath，storageClassName: ""
全集群 一个 StorageClass 都没有 —— 没有 CSI 驱动，全靠路径。
3
路径是 /data/k8s/kubeflow/…
看上去像本地目录。
4
但 /data/k8s 是个软链 → /bdm/share_bdm
5 台机器上都有这同一个软链。
5
服务器1 用 NFS 导出它，5 台机器全部挂载
/etc/exports：/bdm/share_bdm *(rw,no_root_squash,async)　·　fstab：192.168.11.11:/bdm/share_bdm /bdm/share_bdm nfs defaults
6
最终落盘：服务器1 本地 LV vg_app-lv_bdm，100G，已用 56G，剩 45G
这是全平台唯一的持久化落点。
🔴 超卖约 52 倍 15 个 PV 的容量加起来声称 5212Gi（10 个各写 500Gi + 2 个 100Gi + 1 个 10Gi + 2 个 1Gi），但底下是同一块 100G、只剩 45G 的盘 —— 相当于物理盘的 52 倍。任何一个 notebook 写满，全平台一起停。
另外：no_root_squash + * 意味着任意主机都能挂载并有 root 权限；没有快照、没有备份计划。
这就是你说"不想用 NFS，因为单点而且没有备份"的那个东西 —— 它早就是既成事实的根，不是待选方案。

三个要点

1. backend 的 entrypoint 不只是起服务 它顺序做：建软链 → create_db.py → db upgrade（用 Redis 锁 cube:db-upgrade-lock 抢，只有 1 个副本真正执行）→ fab create-admin → myapp init 灌初始数据（后面跟了 || true 吞错）。
推论：砍功能时必须同时摘掉 myapp init 的 seed 数据，否则后端一重启又灌回来。
2. schedule 和 watch 都是单副本 = 各自的单点 schedule 挂了 → 定时任务全停；watch 挂了 → 流水线状态不再更新。
补充：watch 的 16 次重启是设计如此，不是故障 —— liveness 探针里写了 if [ $hour -eq 03 ]; then exit 1; fi，每天 03:00 自杀回收进程。Pod 启动于 09-08，到 09-24 正好 16 天。
3. 只有 backend 和 worker 挂 PVC → 说明只有它们碰文件系统：backend 提供静态文件下载，worker 做数据集备份/拷贝。
schedule 和 watch 不碰盘。

06本次盘点发现的 4 个真问题

都不是"砍组件"能解决的，需要单独排期。

🔴 1. MySQL 是最高风险单点比存储盘还高
和业务负载抢同一台机器
服务器5 同时是 K8s worker，跑着 admin-a855、admin-jupyter 两个 notebook。节点一挂 / 一 drain，数据库跟业务一起没
单点、无副本、无主从
落盘就是 /usr/local/mysql 的数据目录，没看到备份任务
清单和实际对不上
nodeSelector: mysql=true 打在 3 台 master 上，服务器5 没有 → K8s 那套是被跳过、手工裸机装的
存储盘挂了数据还在别的机器上，MySQL 挂了整站登不进去。
🔴 2. 存储：NFS 单点 + 超卖 52 倍
PV 声称 5212Gi，底下剩 45G
10 个 PV 各写 500Gi，全落在同一块盘上。任何一个 notebook 写满，全平台一起停
无快照、无备份
—
权限敞开
no_root_squash + * 任意主机可挂且有 root
⚠️ 3. Redis 无持久化
用的是 emptyDir
Pod 一重启：Celery 队列里在跑的任务丢失、Flask cache 清空。仓库里的 redis/pv-pvc-hostpath.yaml 有 PVC，但实际部署没用上

07一个关键机制：Istio 其实可以绕

如果要评估"能不能不用 Istio"，代码里已经埋了一条降级路径。

调用 create_istio_ingress 的地方 推理服务（view_inferenceserving.py）、服务/中间件（view_serving.py）、NNI（view_nni.py）、notebook（view_notebook.py）、资源清理（view_total_resource.py）
降级路径 py_k8s.py:1758 里有一句：
host = host.split(":")[0]
if not host or core.checkip(host):
    return  # ← 传 IP 就跳过，不建 VirtualService
但是 要走这条路得先有 Ingress Controller 或接受 NodePort 直连。而 install/kubernetes/ingress.yaml 那套 Ingress 对象在集群里没有任何 controller 兜底（kubectl get ingress 为空）。
结论 6 功能下 Istio 不建议砍，绕过成本高于收益。
